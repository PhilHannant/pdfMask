How pdfMask keeps your files on your device

"We never upload your files" is easy to say. This page explains how pdfMask is built so that it's true, and how you can check without taking anyone's word for it.

The short version

  • Your file is processed in your browser. It's read into your device's memory, changed there, and saved back to your device. It is never sent to a server.
  • Every script on the tool pages comes from pdfmask.co.uk. No code from other companies runs on a page that opens your files.
  • Your browser is told to block outside connections. Each tool page comes with a security policy that stops it connecting to any other server.
  • The tools work offline. Once a tool page has loaded, you can disconnect from the internet and it still works.
  • The code is public. Anyone can read it on GitHub.

Check it yourself

1. Turn off your internet

This is the simplest test, and it needs no technical knowledge.

  1. Open a tool, such as Redact PDF, and wait for the page to finish loading.
  2. Switch off Wi-Fi, or turn on aeroplane mode.
  3. Choose a PDF and use the tool as normal.

It works, because nothing needs to be sent or fetched. A tool that uploaded your file couldn't do this.

2. Watch the network

  1. Open a tool page, then open your browser's developer tools (press F12, or Cmd+Option+I on a Mac) and choose the Network tab.
  2. Choose a PDF and use the tool.
  3. Watch the list. On Redact, Merge and the Redaction checker, nothing new appears. On Unlock, you'll see the unlock engine being read from pdfmask.co.uk, and nothing being sent.

3. Read the policy and the code

In the Network tab, click the page itself and look at its response headers for content-security-policy. That's the security policy described below. The same rules are in the _headers file in the public repository, alongside all of the site's code and the tests that check it.

The security policy

Browsers let a website restrict what its own pages are allowed to do, using a Content Security Policy. pdfMask sends a strict one with every page. On the pages that open your files:

  • Scripts can only come from pdfmask.co.uk. Scripts from other sites, and code typed into the page itself, are refused.
  • Redact, Merge and the Redaction checker can't make network requests at all once they've loaded, not even to pdfmask.co.uk.
  • Unlock and Remove PDF password can only fetch from pdfmask.co.uk, which they use to load the unlock engine. They can't connect to any other server.
  • Images, fonts, frames and forms pointing at other sites are blocked too.

The point of the policy is defence in depth. Even if a bug, or a problem in one of the libraries pdfMask uses, tried to send your file somewhere, your browser would refuse to make the connection.

Where the code comes from

pdfMask is built on a small number of well-known open-source libraries, listed on the About page. Each is pinned to an exact version and served from pdfmask.co.uk, not loaded from another company's servers, so the code that runs on a tool page can't change without the site itself changing.

What about visitor statistics?

The information pages, such as the home page and the guides, use Cloudflare Web Analytics to count page views. It doesn't use cookies. It doesn't run on the tool pages: their security policy blocks it. The privacy page has the details.

The limits

No website can prove a negative with a paragraph of text, which is why this page gives you ways to check. A security policy restricts what a page can do, but it isn't a substitute for the code being trustworthy, and you are still relying on your own browser and device being secure.
